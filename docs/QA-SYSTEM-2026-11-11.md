## Lỗi ưu tiên

### P1 — Phiên REST gây NullPointerException sau khi UI đăng nhập

1. Đăng nhập như lượt người dùng đã thực hiện.
2. Home không tải Server/feed; retry vẫn lỗi.
3. Mở Hồ sơ: UI hiện nguyên lỗi Java.
4. Log backend có NullPointerException vì sessionId của User là null.

Vị trí đã đối chiếu: `server/src/main/java/com/denhub/security/SessionManager.java`, method `isValidSessionIdByEmail`; method dùng `findOneWithAuthoritiesByEmail` có Spring cache rồi gọi `existingUser.getSessionId().equals(sessionId)`. `AuthService`/`SessionManager.initSessionId` ghi session bằng bulk update.

**Đã xác nhận:** xử lý null không an toàn và lỗi runtime thực tế. **Chưa xác nhận độc lập:** cache `usersByEmail` có đang trả bản User cũ sau login trong lần chạy này hay không. Cần regression với cache runtime bật và kiểm session/transaction, không kết luận database thật bị thiếu/corrupt hoặc tự đổi dữ liệu.

### P2 — Lộ lỗi nội bộ trên Hồ sơ

Thông báo “Không thể tải thông tin hồ sơ” đi kèm raw Java exception/tên method. Nên trả thông báo an toàn; không để lỗi kiểm phiên trở thành 500 lộ nội bộ. Chưa sửa trong lượt QA.

### P2 — Dữ liệu mẫu che lỗi API

`NotificationsPage.jsx` catch lỗi rồi `setNotifications(devNotifications)`; `RoomsPage.jsx` catch rồi `setRooms(devRooms)`. Trên UI thực tế đã nhìn thấy các mẫu tương ứng. Không coi đây là backend hoạt động được. Việc bỏ/ẩn các routes legacy cần đối chiếu phạm vi nghiệp vụ, không tự thêm Meeting vào scope.

### P2 — Hai toast lỗi hội thoại cùng lúc

Mở `/direct` thấy hai toast “Không thể tải danh sách hội thoại.”. Đã chụp ảnh. Chưa kết luận nguyên nhân là StrictMode hoặc listener trùng nếu chưa có kiểm tra riêng.

### Cấu hình Google OAuth

Console báo origin hiện tại không được phép cho Google Client ID. Cần người quản lý OAuth kiểm tra origin/client cấu hình; không tự tạo khóa, đổi quyền hoặc gửi credential.

### Ghi nhận kỹ thuật bổ sung

- Console có cảnh báo Ant Design deprecated props và React style `@media` trong inline style. Chưa chứng minh chúng gây lỗi nghiệp vụ; ưu tiên sau blocker phiên.
- Source/docs hiện vẫn ghi frontend Channel chưa gửi `request-id` hoặc xử lý queue kết quả mới. Đây là phần đã biết còn dang dở, **chưa được tái hiện qua gửi tin Channel thật trong lượt này** vì không vào được Server QA.
